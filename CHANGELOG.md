# Changelog

All notable changes to the Katab GNOME Shell extension are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

---

## [Unreleased]

### Added
- **DeepSeek V4.1 support**: The DeepSeek provider now targets `deepseek-flash` (V4.1) by default, which supports **native image input** — attach an image and send, no vision-model setup required for Flash. `deepseek-v4-pro` keeps the existing orchestration-based image support, and the retired `deepseek-v4-flash` alias remains selectable (billed as Flash).
- **Time-aware DeepSeek pricing**: Cost and cache-savings estimates now use DeepSeek's off-peak/peak rates (peak = 01:00–04:00 and 06:00–10:00 UTC, Mon–Fri) and cache hit/miss input pricing, chosen from the actual request time.
- **EML email attachments**: The document tool (`/doc`) now accepts `.eml` files. Katab parses them locally with a built-in MIME reader (no external tool) — headers (From/To/Subject/Date, RFC 2047 encoded-words), the text/plain branch of multipart/alternative, HTML-only bodies converted to text, quoted-printable/base64 transfer encodings, and attachment names/sizes.
- **Crawl4AI LLM Extraction (optional)**: Ask the Crawl4AI server's LLM to return structured JSON (schema mode) or a freeform answer (block mode) instead of raw Markdown. New `crawl4ai-extraction-mode`, `crawl4ai-llm-provider`, `crawl4ai-llm-instruction`, `crawl4ai-llm-schema-json`, `crawl4ai-llm-chunk-token-threshold`, and `crawl4ai-llm-overlap-rate` settings. Default stays markdown-only; API keys remain server-side.
- **DeepSeek as the default Crawl4AI LLM provider**: `crawl4ai-llm-provider` now defaults to `deepseek/deepseek-flash`, and both LLM extraction modes ship prefilled defaults (a general-purpose JSON Schema and a summary block instruction) so enabling a mode works out of the box.
- **Inline `/crawl <url>` command**: `/crawl <url>` is now recognized anywhere in a message (e.g. *"Tell me about X. /crawl https://example.com"*), not just at the start or end.
- **Crawl4AI LLM extraction via the sanctioned `/llm` endpoint**: LLM modes (schema/block) now submit to Crawl4AI's `/llm/job` endpoint, which constructs the extraction strategy server-side — so DeepSeek extraction works on secure-by-default v0.9.x builds with no image patching. If `/llm` is unavailable, Katab falls back to Markdown and shows a notice.
- **LLM extraction caching**: Parameter-aware cache entries (URL + schema/instruction/model) prevent re-billing on repeat crawls.
- **Agent-directed docs navigation (`explore_docs`)**: In Deep Research, the model can now explore a documentation site's landing page to get its table of contents (internal-link structure), then `crawl_url` only the pages most relevant to the question — precision navigation instead of a blind site-wide crawl. Agent-only (no footer button / slash command); advertised to the model alongside `crawl_url` under the same web-scraping autonomy gate, and described in the deep-research system prompt.
- **DeepSeek Vision Model support**: Route image attachments through a separately configured vision model (Ollama or OpenAI-compatible) for text-only DeepSeek models (`deepseek-v4-pro`). Two modes: Preprocess (vision analysis injected as context) and Direct (images sent inline).
- **DeepSeek model picker**: Switch between DeepSeek Flash (V4.1) and Pro from the chat header dropdown without opening preferences.
- **Provider switcher in chat header**: Click the provider chip to switch AI backends directly from the chat overlay.
- **Ollama system prompt**: Customizable system prompt for Ollama models, live date injection for all providers.
- **RAG auto-search timeout guard**: `_withTimeout` helper bounds all local service awaits (RAG, Crawl4AI, SearxNG) preventing stuck sends.
- **Request lifecycle state machine**: one lifecycle (`src/core/requestLifecycle.js` — idle → enriching → awaiting-model ⇄ tool-loop → synthesis → stopping → done/error) is now the single source of truth for send/stop state. The re-entrancy guard over slow KB/web enrichment is its *enriching* phase, and the send button, Enter key, chat status, and stop-before-action guards read lifecycle state instead of the legacy `_sendInFlight` flag.
- **Appearance controls now functional**: "Chat Text Size" (Compact / Comfortable / Large) and "Glassy Translucent Dialog" (Preferences → General → Appearance) are now applied by the shell overlay — a root style class scales the whole em-based type scale, and the glass toggle switches the dialog surface between translucent and a higher-contrast opaque surface. The prompt editor also follows the accessibility text-scaling factor again.
- **Deep Research settings page**: Preferences → Tools → Deep Research now exposes the research depth (Standard / Deep / Max) and optional compression / synthesis model overrides, which were previously dconf-only.
- **Budget & notification settings**: Monthly budget amount, warning threshold, and desktop notifications are now configurable in Preferences → General (the shell already rendered budget cards and notifications for these keys).
- **Knowledge Base hardening**: the local RAG stack was audited end-to-end. Collections now use true **cosine** space (legacy L2 collections migrate automatically — embeddings copied verbatim, no re-embedding); indexing results are truthful (cap rejections no longer recorded as successes); BM25 invalidates on every delete/eviction; deleting a conversation purges its KB chunks; chunking applies real overlap; eviction follows `indexed_at`; a `POST /delete` endpoint serves purges; rerank scoring is batched; embeddings keep-alive (30 min) with startup warm-up; storage estimate is TTL-cached and `replace_ids` uses a metadata-filtered lookup.
- **`/kb import` + Preferences imports**: index local files and folders (`txt`, `md`, `pdf`, `docx`, `eml`; up to 50 per import, folders scanned up to 3 levels) into the knowledge base from chat or Preferences → Tools → Knowledge Base → Import Files / Import Folder.
- **`forget_knowledge` tool**: models can delete a stored memory topic, with the same auto/manual confirmation flow as `update_knowledge` (manual mode renders Forget / Dismiss in the KB drawer).
- **`knowledge_search` collection filter**: the model can restrict a KB search to `conversations`, `documents`, or `research_cache`.
- **Research-cache re-import + `read_url` indexing**: "Re-index" rebuilds research content from `research-cache.json`, and page text fetched by the Read Page tool is indexed alongside web search/crawl results.
- **KB usage warning**: a once-per-session warning at 80% of a collection's chunk cap explains auto-pruning.
- **RAG service versioned + tested**: `rag-service/server.py` now lives in the repo with `make sync-rag-server` / `make test-rag-server` (31 unittest cases) and per-stage timing logs (embed / dense / bm25 / rerank).
- **Progressive web browsing (link-aware page results)**: `read_url` and `crawl_url` results now include a compact "Links on this page" section (internal + external, noise-filtered, bounded), so the model can follow a promising subpage instead of re-running a broad search when the answer is one click away. `read_url` extracts the links from the fetched HTML; scraped results reuse Crawl4AI's link lists, and the section survives progressive context truncation.
- **Deep Research subpage following**: after a branch's initial crawl, Katab scores the links found on the scraped pages against the branch query and follows the most relevant few — one level deep, bounded (Preferences → Web Scraper: "Follow Subpage Links in Research", default 3 links per branch, 0–10). Research now always crawls raw Markdown so link discovery and code preservation work, and the compression stage decides what to summarize.
- **Decision-based AI extraction for the crawl tool**: `crawl_url` gains `mode` (`content` default, `extract`) and `instruction` arguments. The model receives raw page Markdown unless it explicitly requests server-side LLM extraction, and every extraction result ends with a "Raw content available" pointer telling it how to re-crawl the same URL with `mode="content"` for verbatim text or code.
- **Code-aware research compression**: code-heavy pages (docs with code samples, API references) skip the research compression LLM and contribute a bounded verbatim code excerpt to the branch findings instead — research keeps the actual code rather than an AI paraphrase. If Crawl4AI's content filter drops code blocks from a page, Katab now prefers the unfiltered Markdown.
- **Archived conversations**: the history panel now has **Active** and **Archived** tabs (with counts). Archive any conversation from the row actions to hide it from the active list, the recent-chats dropdown, and the panel menu — nothing is deleted, and it can be unarchived from the Archived tab at any time.
- **Conversation titles & descriptions**: every saved conversation's title and optional one-line description can now be edited manually (pencil button in the history list) or drafted with **Generate with AI**, which summarizes the conversation using the active provider — the suggestion lands in the editable fields, and nothing is saved until you press Save. Manual/generated titles survive auto-saves, an empty title restores the automatic first-message title, and descriptions appear under the title in the history list.

### Changed
- **Freed browsing limits**: Max Tool Iterations now defaults to 25 (range 1–100) and Deep Research follows that preference (with a minimum of 12) instead of a hardcoded cap of 12; the context-based force-synthesis trigger waits until 85% of the provider's real input budget; tool-result truncation tiers are ~30–50% more generous; the per-query result cap is 20 → 30; a strong knowledge-base match no longer hides `web_search` from the model (it still suppresses Katab's automatic fallback search); and the search-count / repeated-failure guidance is advisory instead of hard-stop ("STOP SEARCHING" / "Do NOT call read_url again" removed) so a model on a close trail can keep browsing.
- **Preferences maintainability overhaul**: `prefs.js` (once a single ~4,900-line method) is now an 86-line orchestrator. Every page lives in `src/ui/prefs/` modules — a shared `widgets.js` context factory plus `generalPage`, `ollamaPage`, `deepseekPage`, `providerPages`, and `tools/{index,document,webSearch,crawler,knowledge,deepResearch}`. UI layout, labels, and behaviour are unchanged.
- **Shell UI decomposition**: `_buildUI` (1,037 lines), `_addChatMessage` (593), and the `_readSSE` EOF finalization were split into focused methods (`_handleStreamEnd`, thinking/tool-log/pill builders, ten `_build*` UI methods). No behaviour changes.
- **Developer tooling**: `make check` now genuinely validates every JS file as an ES module (`node --input-type=module --check`), test suites are auto-discovered from `tests/*.test.js` (fixing two suites the old `test-verbose` list silently skipped), `make reload` / `make logs` shortcuts were added, and a GitHub Actions CI workflow (extension checks/tests/package + RAG service tests) runs on pushes and PRs. Two dead tool-schema builder exports were removed — the tool registry is the single schema source.
- **Lint & format baseline**: ESLint (GJS globals, conservative correctness rules) and Prettier now cover the codebase — `make lint`, `make format`, `make format-check` — and `make check` gained two guards: a stylesheet delimiter-balance check (`scripts/check-css.mjs`, which catches the stray-brace class of error that once blocked the extension from loading) and a GJS import smoke test over `src/` modules (`scripts/import-smoke.js`, which catches module-resolution errors `node --check` cannot see). CI installs the npm tooling and enforces both.
- **Shared internals**: capped HTTP body reading is now one `src/shared/httpBody.js` helper used by the web search, web scraper, and RAG tools (previously three copies), and DeepSeek billing rates moved to `src/usage/deepseekPricing.js` shared by the chat cache-savings estimate and the token ledger — the duplicated rate cards can no longer drift.
- **Provider catalog**: provider labels, icons, the DeepSeek model list, selection-row accent classes, and the preferences-page provider copy now live in `src/providers/catalog.js`, shared by the extension and the preferences window.
- **KB relevance thresholds recalibrated**: auto-inject ≥ 0.55, web-suppression ≥ 0.72, fallback floor ≥ 0.45 — calibrated for true cosine scores (the previous 0.35 / 0.70 / 0.10 values assumed an L2-derived scale).
- **KB send-path budgets**: auto search 3s → 8s, tool search 10s → 15s, manual `/kb` 15s → 20s; auto search is skipped outright when health reports embeddings down, and trivial prompts (greetings / one-word continuations) skip auto search entirely.
- **`update_knowledge` tool results**: now report the real outcome — "saved", "queued for user confirmation", or "FAILED" — instead of always claiming the update was initiated.
- **Health diagnostics**: `/health` now probes the Ollama embedding backend and returns an `embedding` block; search/index embedding failures return structured 503s instead of tracebacks.
- **Tool-call log UI**: Redesigned to VS Code-style with teal accents, animated spinners, expandable query/URL drawers.
- **Tool footer buttons**: Redesigned as compact horizontal chips matching footer row height.
- **Synthesis prompt**: Changed from branch-summary to topic-driven, centering the user's original question.
- **Raw fact injection**: Deep research synthesis now includes granular `{claim, url}` facts alongside compressed summaries.
- **Context budget**: Adaptive proportional truncation with 80K-char budget for synthesis.
- **Autonomous tool-loop limits now follow the Max Tool Iterations preference**: The force-synthesis iteration trigger uses `web-search-max-tool-iterations` (default 25) instead of a hidden fixed cap of 5, and the context trigger scales to 85% of the provider's real input budget instead of a flat 40K-char payload limit that fired after a single tool batch in any long conversation — the model can now chain as many tool rounds as configured before being forced to answer.
- **Ollama deep research**: Fixed timeouts and think-mode blocking during synthesis for local models.
- **Offscreen framebuffer**: Removed `border-radius` and `box-shadow` from all chat content area elements to eliminate GPU texture errors on long responses.
- **Mid-reply close/reopen guards**: UI update functions now check dialog open state before manipulating widgets.
- **Hybrid KB retrieval scores normalized**: The RAG service now returns 0–1 similarity scores for hybrid (BM25 + dense) searches instead of raw reciprocal-rank-fusion values, so coverage/confidence thresholds and the UI percentage reflect real relevance.
- **Incremental conversation indexing**: Only newly added messages are embedded into the knowledge base, instead of re-embedding the whole conversation on every new message.
- **KB search caching**: Repeated identical knowledge-base queries within 60s reuse cached results instead of re-embedding the same text.
- **Chat UI legibility overhaul**: The overlay type scale is now em-based (tracks the user's UI font and accessibility text scaling) at a comfortable size — body ≈12pt, meta 9.5–10pt, hard 9pt floor — with enforced contrast floors in both themes (dark secondary ≥0.72 alpha / light ≥0.66, hints ≥0.58/0.55). Sender labels, timestamps, metrics, tool-call details, session-info rows, history rows, KB/cache drawers and footer labels are all larger and brighter; the light dialog surface no longer lets desktop text bleed through.
- **Glassy dialog translucency**: The dialog surface is slightly more see-through by default for the glass look, with a new "Glassy Translucent Dialog" toggle (Preferences → General → Appearance) that switches to a more opaque, maximum-readability surface. A real-time backdrop blur was prototyped and removed: Shell.BlurEffect's background mode cannot allocate its offscreen buffer on some GPUs (journal floods with "Failed to create offscreen effect framebuffer"), and the clone-based actor mode renders nothing on GNOME 46.
- **Chat Text Size preference**: New Appearance section on the General preferences page with Compact / Comfortable / Large. Comfortable is the default and scales every em-based overlay size from one root class.
- **Prompt editor respects text scaling**: The prompt font was hardcoded to `Sans 11.5` and ignored the accessibility text-scaling-factor; it now scales with the setting (clamped 11–20pt) and matches the Comfortable scale.
- **Dead code/CSS cleanup**: Removed ≈600 lines of superseded code (legacy usage-card builders, the mock response helper, unreferenced attachment/formatting helpers, and the write-only `crawlAsync` whose poll endpoint was wrong) plus orphaned CSS rules (old footer tool-chip family, prompt-entry, citation-inline, usage face/pill selectors) and invalid St CSS declarations that were silently ignored. The never-functional inline-SVG charts option was removed from deep research — the chat surface is a Pango text renderer and cannot display SVG.
- **Unused tool-runtime methods removed**: `Crawl4AIRuntime._buildCrawlPayload` / `_parseNetworkRequests` (superseded by the exported pure functions), `DocumentToolRuntime.getCapabilities()` (the module-level `getDocumentToolCapabilities()` is the live API), and `RagRuntime.deleteCollection` / `clearAll` / `exportData` (never called — the preferences window performs KB maintenance through the maintenance-signal + HTTP paths) were deleted along with the corresponding test case.
- **Theme-aware citation markers**: Inline `[N]` markers used a hardcoded teal that was nearly invisible on light backgrounds; they now follow the theme (dark teal / deep teal).
- **KB result snippets fully readable**: Removed the double clamp (wrap + ellipsize) that cut history-view knowledge-base snippets to fragments.
- **Incremental conversation indexing**: Only newly added messages are embedded into the knowledge base, instead of re-embedding the whole conversation on every new message.
- **KB search caching**: Repeated identical knowledge-base queries within 60s reuse cached results instead of re-embedding the same text.

### Fixed
- **Context-window gauge numbers corrected and stabilized**: attached images are charged a fixed per-image token cost instead of their base64 payload length (a single photo previously read as ~1M tokens and could evict the entire text history from the context budget); the draft-token probe is sequence-guarded so a slow `/tokenize` response for an older draft can no longer flash a stale number or resurrect the draft after sending; the payload cache now invalidates on every input that affects it (deep-research mode, provider context size / model, system-prompt text, attachment cache, KB availability, tool-iteration cap); a non-positive Ollama/Unsloth context size falls back to the default instead of producing a zero budget that silently dropped all history; and context sizing no longer miscounts DeepSeek reasoning echoes (they are included, as sent).
- **Context sizing is O(n) instead of O(n²)**: `splitHistoryForBudget` and the Ollama message truncator now compute per-message sizes once and combine them with prefix sums instead of re-serializing the whole tail on every drop candidate — long conversations no longer cause main-thread stalls during tool loops and gauge refreshes (the Session Info popup also reuses the already-computed history for Anthropic instead of building it twice).
- **Sources list no longer floods with navigation links**: the "Links on this page" sections added to `read_url`/`crawl_url` results were being harvested by the message Sources collector — a single page could add 25+ unvisited links as if they were accessed sites. The collector now ignores the links section (pages that were actually followed still appear through their own tool calls), and title generation no longer inflates the Deep Research "Pipeline (cumulative)" figure in Session Info.
- **`read_url` tool-log detail always showed "Page fetched"**: the log line read a non-existent `page.content` field (the extractor returns `page.text`), so the extracted size was never displayed.
- **Synthesis quality gate now actually runs**: the DeepSeek non-XML regurgitation gate (retry once with a stricter quality-gate prompt + trimmed tool history) sat behind an earlier `_forceSynthesisActive` branch that always matched first, so it was dead code — degraded syntheses were accepted silently. The gate is now evaluated first (XML-style tool markup still routes to the existing stripping/retry path).
- **Preferences markup warnings**: group titles and row descriptions/subtitles containing `&` or `<…>` (e.g. "Connection & Model", "Set Up & Start", `LLM_PROVIDER=<same value>`) are now Pango-escaped, eliminating libadwaita's "Failed to set text … from markup" journal warnings and the dropped-text risk they carry.
- **Ollama tokenize probe**: the draft-token counter probed a non-existent `/api/tokenize` endpoint on every typing pause (Ollama has no such API), 404-ing each time. The probe now uses a dedicated session, caches "unsupported" per provider after the first failure (logged once, `[Katab:tokenize]`), and falls back to the character estimate; the shared Soup session timeout is no longer mutated by typing.
- **Auto-retry no longer races a fresh send during knowledge-base enrichment**: the post-synthesis quality retry now checks the full request lifecycle (`canSend()`) before starting and before re-synthesising, so it cannot clobber a new message whose KB/web enrichment is still in flight.
- **Typing no longer fires a doomed tokenize request at Ollama**: draft token counting probed `{ollama-url}/api/tokenize` — a route Ollama does not serve — on every debounced typing pause, always failing over to the `chars/4` estimate. The probe now uses a dedicated session (it never touches the shared request session's timeout), and a 404/405 response is cached per provider so the estimate is used without re-probing for the rest of the session. A one-line `[Katab:tokenize]` journal entry records the fallback.
- **Unparseable quality-check response no longer records a blank result**: when the evaluator returned text without a usable score, the coverage value was `undefined` and bypassed the skip guard, storing a quality result with no score. It is now treated like the parsed-but-unscored case: logged and skipped.
- **Doubled endpoint suffix fixed**: a provider base URL that already ended with a path segment (e.g. `…/api/chat`) no longer receives the suffix twice (`…/api/chat/api/chat`) — streaming and non-streaming endpoint normalization now strip trailing slashes before the suffix check.
- **DeepSeek tool advertisement fixed**: when web search is disabled or suppressed while crawl/RAG tools are active, `web_search`/`read_url` schemas are no longer advertised — each tool family now gates independently, matching the other providers and the context estimator.
- **Model "stuck in another mode" / mangled answer after tool calls**: In any conversation whose payload exceeded 40K chars the first tool batch instantly triggered force synthesis (tools silently removed from the request), so the model could never chain more than one tool round per turn — and its follow-up tool calls leaked into the final answer as raw XML text (mangled fragments like `< calls>`) because the "recovered prose" heuristic accepted the partial strip. The context trigger is now scaled to the provider's real budget (75% of input budget, DeepSeek ≈ 1.6M chars), degraded tag variants with spaces or a missing `tool_`/`function_` prefix are normalized and stripped, and mangled markup is routed to the synthesis retry instead of being rendered to the user.
- **KB hybrid search could return deleted or evicted content**: the BM25 corpus was never pruned, so replaced facts, evicted chunks, and deleted conversations could resurface in hybrid results. Deletes now invalidate the corpus, which is rebuilt lazily from ChromaDB.
- **Rejected KB indexing was recorded as success**: `indexed` stayed non-zero when a cap blocked storage, marking conversations as indexed although nothing was stored. Success is now gated on stored chunks, rejections surface a warning, and the reconcile pass counts only real successes.
- **"Re-index" / "Clear KB" did nothing until a shell reload**: the in-memory sentinel was rewritten to disk after maintenance, so stale index state resurrected. Maintenance now signals the running extension (generation + action settings); Re-index rebuilds immediately and Clear stays cleared.
- **Deleting a conversation left its KB chunks searchable forever**: deletion now purges the conversation's chunks via `POST /delete`.
- **Duplicate conversation re-embedding**: concurrent save points could re-embed the same growing conversation (4× in one turn in the journal). Indexing is now deduped per conversation while in flight.
- **Chunk overlap was silently unused / could crash**: overlap is now applied at chunk boundaries and clamped to half the chunk size (overlap ≥ size previously raised a server error).
- **KB embeddings outage caused a silent wait per message**: the send path now fails fast with an actionable notice ("embeddings unavailable — is Ollama running?") and retries automatically within 3 minutes.
- **`read_url` results were never indexed**: page text fetched by the Read Page tool is now part of the research cache.
- **Clicking Deep Research (and other lower tool rows) closed the chat window**: Every floating popup — the tools gear menu, Session Info panel, and recent-chats dropdown — is a child of the full-screen overlay actor, which is pinned to the **primary monitor's origin** (not the stage origin; e.g. a laptop panel sitting at +480 y below an external display). Popup positions were computed from stage coordinates but passed straight to `set_position()` (parent-relative), so every popup rendered offset by the monitor origin — pushing the lower half of the tools popup (Deep Research, Knowledge) outside the dialog rectangle, where the stage click handler treats a click as "outside" and closes the chat. The click never reached the row (the mode didn't toggle) and the window vanished. Popups are now converted to overlay-local coordinates with monitor-based clamping, and clicks on any visible floating popup can never trigger the click-outside close. The dialog also dismisses all floating popups on close so reopening starts clean, and re-anchors visible popups after monitor/geometry changes. A one-line `[Katab:tools]` placement trace is logged per popup open for future geometry diagnosis.
- **Deep Research row could silently flip a mode that cannot run**: When neither Web Search nor Web Scraper is available the Research row renders disabled; clicking it now explains how to make it usable instead of silently toggling a mode that would fail at send time.
- **Auto KB enrichment disabled by hybrid scores**: With `rag-hybrid-enabled` on (the default), the RAG service returned tiny RRF rank scores (~0.03), so the pre-send auto KB search never injected context, KB→web suppression never fired, and the KB pill showed ~3% for everything. Hybrid results now report normalized 0–1 scores.
- **`update_knowledge` never replaced old facts**: Knowledge updates used a fresh timestamped id each time, so outdated facts for the same topic accumulated and could resurface. Updates now use a stable per-topic id so re-updating replaces the previous fact, and indexing failures are surfaced in the KB pill instead of always reporting success.
- **KB history search snippets truncated**: The history-view KB results clamped each snippet to 3 characters. Full snippets now render.
- **BM25-only results lost metadata**: Keyword-only matches dropped source/title/URL/session metadata, breaking source labels and click-to-open. The service now preserves per-chunk metadata.
- **Document attachments not indexed**: The "Index Document Attachments" toggle had no effect. Parsed text documents are now indexed into the KB (respecting the toggle and the memory master switch).
- **KB tools stayed disabled after a transient outage**: one failed health probe withheld KB tool advertisement and the auto KB search until the next shell reload. The service-down state now expires after 3 minutes (matching the embeddings-down window) so a recovered service is retried automatically.
- **Transient startup health-probe failure could stick for the session**: if the single startup probe missed (busy shell during extension enable, service mid-restart), the KB stayed marked unreachable until a reload even though the service was fine. The extension now retries the probe with 10s/30s/90s backoff, logs the underlying error (`code: message`), posts the "not running" notice only once a retry confirms the outage (~10s in), and announces "back online" on recovery. The start hint now suggests `systemctl --user start katabai-rag`.
- **KB health probes could wedge and never recover (suspend/resume)**: a request stuck in the client's HTTP session — observed after a laptop suspend/resume cycle — could hang a probe without ever surfacing an error, silently stalling the whole retry chain (a scheduled retry never ran). Health probes now have a hard 12s upper bound, recreate the RAG client session on timeout, and re-probe automatically right after system resume (login1 `PrepareForSleep`). The service also bounds every Ollama call (4s connect; 6s/240s/180s read) so an unreachable or black-holed Ollama — e.g. a remote AI PC over Tailscale — returns a fast, clean `embedding.ok=false (timed out)` in ~4s instead of hanging request handlers for ~2 minutes (validated against an unroutable address). While embeddings are down, the extension re-probes every 3 minutes so the KB recovers on its own once Ollama returns — e.g. when a remote AI PC wakes from sleep.
- **Queued KB import lost when the Knowledge Base was disabled**: the Preferences import queue file was consumed before the enabled check. It is now retained with a notice and processed once the KB is re-enabled.
- **Cached KB searches could mislabel the retrieval mode**: the search cache stored the client's flags-based guess instead of the mode the service actually ran. Cache hits now report the service mode (e.g. plain `dense` when the BM25 index is unavailable). The `/health` probe also fetches the Ollama model list once instead of twice — halving health latency when Ollama is unreachable.
- **Background notices could throw during chat teardown**: `_addSystemMessage` now appends defensively — startup health/import notices queue while the dialog is hidden and are dropped safely after the UI is destroyed (previously an unguarded `add_child` on a destroyed actor).
- **History save reliability**: `_readSSE` EOF handler now has its own try-catch with fallback save; `HistoryManager.flushSync()` called after every assistant response save.
- **`Array.filter()` reference detach bug**: `HistoryManager.saveConversation` now mutates cache in-place (no more silently lost assistant responses).
- **History reload blank-bubble bug**: Tool-call intermediary messages and Anthropic tool-result arrays now filtered from UI replay.
- **Ollama stream timeout**: Local Ollama requests no longer time out (was 30s, now unbounded).
- **Tool-call UI disposed widget errors**: `_responseUiAlive` guards prevent accessing destroyed widgets during async tool execution.
- **Prompt character cap**: Large paste handling with truncation notification.
- **Inline citation buttons**: `[N]` markers in deep research reports are now clickable, bibliography parsed from assistant output.
- **Enter-stacking**: Multiple rapid sends are blocked by the request-lifecycle guard while KB/web enrichment is in flight.
- **Welcome new-chat scroll**: New Chat after loading a long conversation now resets viewport and prompt text.
- **Silent crawl success path**: A successful scrape produced no `[Katab:crawl4ai]` journalctl lines (only failures/cache hits logged). The success path now logs the scrape start (mode + provider + URLs), `/llm/job` submission and completion (with output sizes), markdown per-URL results, and a `/crawl command → scraping` trigger line.
- **Raw `/crawl` text leaking into the RAG auto-search query**: With an inline `/crawl <url>` command, the RAG web-search fallback searched the raw command text. Added `stripCrawl4AICommand` so the auto-search query and the model-visible user message keep only the conversational part (e.g. "tell me what this page is about").
- **Redundant RAG enrichment for direct `/crawl <url>`**: The auto KB search + low-coverage web-search fallback no longer run when a direct `/crawl <url>` command is active — the scraped page is the authoritative source, so the supplement (often rate-limited or unrelated) is skipped and logged as such.
- **Crawl4AI LLM setup instructions**: GSettings descriptions, Preferences text, User Guide, and API reference now document that the LLM provider must be allowed server-side — set `LLM_PROVIDER` (matching the Katab `crawl4ai-llm-provider` value) plus the provider's API key (e.g. `DEEPSEEK_API_KEY`) in the container's `.llm.env`, then restart with `docker compose down && docker compose up -d`. Documented the `/llm/job` endpoint as the sanctioned LLM-extraction path.
- **Research plan revisions replacing the plan**: Sending a follow-up prompt while a research plan is pending approval (e.g. *"the year is 2026, not 2025 — update it"*) used to be treated as a brand-new research query, regenerating the whole plan from scratch. Follow-ups during the plan phase are now routed through a revision planner that edits the existing plan in place — preserving the original query, angle structure, and unchanged details while applying only the requested corrections. An explicit `/research` command still starts a fresh plan, and if a revision fails the pending plan is left untouched. Revisions don't consume the Deep Research turn, so a one-shot `/research` keeps its deep-research thresholds through the eventual execution, and the plan phase routes correctly even if the mode was toggled off meanwhile. Added a **Cancel plan** button to the plan card (previously `_cancelResearchPlan` was unreachable); cancelling now also turns Deep Research mode back off so the next message behaves like a normal chat.
- **Research grinding on a dead search/scrape service**: When SearxNG or Crawl4AI was unreachable (offline), the research pipeline retried the same connection failure at every level — 3 attempts per query inside the search runtime, 2 fallback engine configs, then 2 branch retries — for *every* branch in the plan, with no abort, then continued into gap analysis/synthesis on empty findings. Connection failures are now treated as a **service-down** condition: `_attemptSearch` throws `connection-failed` on the first connection error instead of retrying, the research branch loop (and the gap-filling refinement phase) abort the whole run on the first `connection-failed`/`network-error`, marks the remaining branches as failed in the timeline immediately, and surfaces a clear message explaining that the web search / scraping service is unreachable and to start it before running research again. Research mode is turned back off and the checkpoint is cleared so a broken run isn't resumed.
- **Research plan sometimes skipped (empty planner response)**: The planner occasionally received a malformed, verbose, or wrong-schema response from the model instead of the required JSON array. A single unparseable response discarded the entire planning phase and fell straight into tool use/answering with no plan. The planner (and the plan-revision planner) now retry once with a format nudge when the response isn't a valid plan, and log a truncated sample of the raw response to the journal for diagnosis.
- **Research couldn't be stopped manually**: During research execution (the branch phases), the run had no cancellable wired up and the streaming state was false, so the send button stayed "Send" and pressing it started a new message instead of stopping the research — a long run could only be stopped during plan generation or the final synthesis stream. Research now sets up a cancellable + streaming state when it starts (the send button becomes "Stop"), `_isRequestCancelled` also recognizes the structured `'cancelled'` error code so a stop between branch retries is honored, and pressing Stop cleans up the research UI and state with a "Research stopped." message (mode returns to normal chat). This is consistent across all phases (branch execution, gap analysis, refinement, and the final stream), and a `finally` block releases the research-run streaming state whenever the run ends without a synthesis stream so the send button never stays stuck on "Stop" (which would drop the user's next message). Stopping or a service-down abort now also clears the research checkpoint, and checkpoint resume only happens when it belongs to the **same research query** — a stale checkpoint (e.g. left by a stop, or a reload followed by a new question) can no longer overwrite a freshly generated plan with an unrelated one.
- **OpenAI mini-model cost estimates were up to 16× too high**: Cost estimation matched pricing keys by prefix in table order, so `gpt-4o-mini` inherited `gpt-4o` rates ($2.50 vs $0.15 per 1M input) and `o1-mini` inherited `o1` rates. Pricing now matches the most specific key first, with regression tests for mini models.
- **Light-theme readability**: Error diagnostics (`.katab-error-title` / `-details-label`), KB relevance badges, the token gauge's reserved segment, and preference status badges ("Built in" / "Detected" / "Install") used pastel colors with no light-theme overrides — error details were effectively invisible on the light dialog. All now have dark-on-light variants matching the file's contrast floors.
- **Manual `/search` hid connection failures**: The category fan-out converted any search error into an empty result set, so a down SearxNG reported "No results found". Total failures now surface the real error (service down, JSON format disabled, HTTP error) while partial failures still return what succeeded. A duplicate re-ask also no longer waits out the empty-result cooldown before returning.
- **Intent-based search routing**: `classifyQueryIntent` / `ENGINE_ROUTES` (code → StackOverflow/GitHub, news → news, …) were computed but silently discarded by the default category fan-out. Intent routes now take priority over the generic fan-out.
- **`web_search` tool arguments**: The advertised `time_range`, `categories`, and `limit` parameters were ignored by the executor; they are now applied, and the results-per-page default in the tool description was corrected (5, capped at 20).
- **Unbounded memory growth in caches**: Parsed attachments (including full base64 image payloads) were cached for the entire shell session with no eviction, and Crawl4AI/RAG HTTP responses were buffered without a size cap. The document cache is now LRU-capped and cleared together with the session attachment cache, and both service clients use the same bounded streaming reads as web search.
- **Research compression failures were silent**: Page compression, summary merge, theme clustering, and section drafting returned fallback values with no log line, making provider outages indistinguishable from "no facts found". Failures (including cancellations) are now logged.
- **Session-memory fold prompt overflow**: The fold request serialized the entire folded transcript into a single prompt; on small-context providers the instructions could be truncated away before the model saw them. The transcript is now bounded to the provider's context budget, keeping the newest folded messages.
- **`/doc` matched any word starting with "/doc"**: Prompts like "/docs are great" opened the file picker instead of being sent. The command now requires a word boundary. A bare `/kb` is now recognized so the "add a query" hint appears instead of sending a literal "/kb" message to the model.
- **Misc robustness**: The research cache only clears its dirty flag after a successful write (failed flushes retry instead of silently dropping the mutation); presets no longer vanish silently when `presets.json` is unreadable; crawl cache hits re-validate SSRF/DNS before serving; PDF download errors report the real HTTP reason phrase; KB (`knowledge_search`) results now participate in iteration-based truncation like the other tools; and the DeepSeek vision-model guard in Preferences no longer warns for the vision-capable Flash family.

### Security
- **SSRF protection extracted to shared module**: `src/shared/networkGuard.js` used by both `webSearchTools.js` and `crawl4aiTools.js`.
- **Web content safety policy**: Injected into system prompts for all providers when web tools are active.
- **KB retrieval treated as untrusted**: knowledge-base results carry a "reference data, never instructions" notice, and the web-content safety policy applies whenever KB context is present (the KB can contain previously crawled web text).
- **`forget_knowledge` scope limits**: the forget tool only deletes memory-fact chunks (`update_<slug>` ids) — never documents or conversation history — and manual mode requires explicit user confirmation.
